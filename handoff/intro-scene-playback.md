# 介绍页分幕播放试验

原先的光线、转身和台词都根据滚动位置计算。滑动慢时，画面可能停在半亮状态。滑动快时，访客可能越过还没看清的台词。用户提出按幕切换，在讨论后选择试做固定节奏与跟手退场结合的版本。

- 黑屏保留小箭头。点箭头，或通过滚轮、触屏纵向手势和键盘进入单人肖像。前三幕分别以约 0.82、0.76、0.76 秒完成入场，五人合照约 0.86 秒。停手后，当前幕会播完并留在原位。再次操作可在播放途中换幕，反向操作可回到上一幕。
- 触屏按一次完整手势换一幕，同方向且连续到来的滚轮事件按一次手势处理。抵达五人合照后，下一次向下的手势使用原生滚动，黑底画面按滚动距离向上离开，手势反向时可推回合照。书架露全后可操作。
- 手势实现见 [introGestures.js](../homepage/introGestures.js)，各幕的播放时长和退场见 [scrollScenes.js](../homepage/scrollScenes.js)。减少动态效果或关闭脚本时，介绍可静态浏览，页面底部提供书架入口。
- 普通与满架构建通过。Chrome 本地验证了连续滚轮事件只推进一幕、停手播放完成、键盘向前与向后切换、模拟手机触屏手势、合照跟手退场、书架落点及回访。手机真机手感和性能尚未测量。
- 用户提出分幕交互并决定试做混合方案。Agent 实现并完成本地验证。

## 触控板换幕卡住 · 2026-11-16

- 用户反馈触控板滑动有时无法换幕，键盘可正常切换。Chrome 本地模拟一轮逐渐衰减的滚动事件后紧接一次同向轻扫，旧版仍停在当前幕。旧规则要求等待事件完全停顿，惯性持续时会把新轻扫算进上一轮。略带横向分量的小幅滑动也容易被过滤。
- 调整 [触控板滚动识别](../homepage/introGestures.js)。小幅纵向滚动可以累积，低速惯性后再次加速可换幕，明确的反向滑动可返回上一幕。惯性继续衰减和微小抖动时保持当前幕。合照退场段继续交给页面原生滚动。
- 普通与满架预览构建通过。Chrome 模拟复现旧版失效，并验证新版可以衔接换幕。还覆盖了轻微斜滑、反向、抖动、键盘、触屏及合照退场。等待用户在原触控板上复测。

## 分幕入场与退场交接 · 2026-11-16

- 用户反馈换幕时上一幕消失得突然。原实现立即隐藏上一幕，下一幕才开始打光，交接缺少重叠。
- 上一幕保留当前光线与人物姿态，在约 390 毫秒内轻移淡出，下一幕同时开始打光和入场。中途反向时，从仍可见的画面接回。五人合照到书架继续使用滚动距离控制。
- 本地普通和满架构建通过。Chrome 在桌面及手机宽度验证了两幕短暂重叠、快速连续换幕、中途反向和合照退场，并复查滚轮、模拟触控板、触屏与静态入口。

## 书架入场固定时长 · 2026-11-16

- 用户在手机上观察到，前面几幕改成固定节奏后卡顿明显减少，因此决定将合照到书架的退场也改为固定播放。合照亮相后，下一次下滑触发约 680 毫秒的上移。黑底合照移出视口时，暖白书架从下方露出并轻微上移，动画结束立即可以选书和换排。
- [介绍页控制](../homepage/scrollScenes.js)在识别手势后启动 CSS 位移动画，并在动画结束时进入书架。[合照退场样式](../homepage/styles/portrait.css)与[书架入场样式](../homepage/styles/bookshelf.css)共用时长。播放中连续输入不重复触发，播放前可以反向回上一幕。
- 普通和满架构建通过。Chrome 本地验证了桌面滚轮、键盘、模拟手机滑动、固定时长、返回介绍、书架换排、减少动态效果及无脚本入口。手机真机性能尚未测量。
- 用户提供手机体验反馈并决定将最后一段改成固定播放。Agent 实现并完成本地验证。

## 限制快速滚轮连跳 · 2026-11-16

- 用户反馈向下快速滚动可连跳几幕。原先的手势识别会把相隔超过约 105 毫秒的滚轮输入判断为多次操作，因此可能在台词亮相前就换幕。
- 向下滚轮换幕前须等当前入场播放至约 88%，常规单幕约 0.67–0.76 秒。期间的向下滚轮输入直接丢弃。反向滚轮、键盘与触屏沿用原有切换方式。进入书架前，五人合照也受同一限制。
- 普通及满架构建通过。Chrome 本地验证快速滚轮连发只能推进一幕，停手后无延迟跳转，新的下滑可继续，反向可立刻返回，键盘和书架入口正常。

### 回退滚轮间隔

- 用户试用后反馈换幕手感不自然，决定回退 `a002edc` 的滚轮等待规则。本地页面源码与已发布的固定时长书架入场版 `14eb053` 一致。普通及满架预览构建通过。

### 修复触控板连续快滑卡住

- 本地模拟复现了两次同向快扫间隔很短时卡在同一幕。旧规则等待幅度降到固定低值或事件停止，强惯性仍在时会忽略下一次加速。
- 识别一段明显减速之后的重新加速，让新快扫可以推进一幕。持续衰减仍按原手势处理。
- 普通和满架构建通过。Chrome 模拟验证快扫、惯性衰减、轻扫、斜滑、抖动、反向和书架入口。实际触控板待复测。
