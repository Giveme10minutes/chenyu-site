# 网站改动记录模板

每项实际改动在 [开发进度](progress.md) 留一条记录。同一问题的几轮迭代写在一起。文案、样式等小改动直接记在进度里即可。涉及多个环节的排查、上线事故、较完整的功能或有对照数据的优化，可以在本目录写一份独立记录，再从进度链接到它。

## 进度记录简版

```md
### 改动主题 · YYYY-MM-DD

- 问题与改动。原来在什么场景出现什么问题，或想改善什么体验。这次具体改了什么。
- 验证与状态。测试了哪些页面和操作，得到什么结果。写明本地、线上或待验证，有相关提交或部署链接可附上。
```

## 复杂改动或简历素材版

```md
# 改动主题

- 背景与目标。涉及的页面、用户操作和预期体验。
- 现象与排查。复现步骤、设备或浏览器、观察到的证据。原因尚未确认时注明。
- 方案与取舍。最终改动、关键源码位置，以及为什么选这个办法。
- 验证与结果。记录测试环境、通过的操作和未覆盖的部分。涉及性能时保留测量条件与前后结果，说明是真机还是模拟。
- 个人贡献。区分用户本人已确认的工作与 Agent 协助完成的工作。待用户确认的部分标注为待确认。
- 证据。按实际情况附源码、提交、部署记录、截图或录屏。
```

写简历时，从这些记录里挑能够说清问题、技术判断和验证结果的工作。依据用户确认的范围描述个人贡献，用实测结果支持量化表述。公开记录只放适合公开的证据。
