# 博客内容维护计划

双排书架与蝴蝶转场已能在本地预览。书架目前读取 `homepage/bookshelfEntries.js`，其中包含演示内容和空白测试书。下一阶段先打通「写一篇文章 → 书架出现一本书 → 点开阅读 → 返回原位」。

## 你以后怎么加内容

1. 选「生活记录」或「做过的项目」，新建一个文章文件夹。写正文，把可公开的照片或项目截图放在同一个文件夹。
2. 在正文开头填标题、短书脊名、日期和摘要。有封面就写文件名，缺图时由网站生成文字封面。
3. 本地构建后打开书架，检查封面和正文。也可以把正文和图片交给 Codex，在本地排好并给出预览链接，再决定发布。

两类内容共用一套结构。生活记录按需要放照片和文字。项目记录可以写要解决的问题、自己的工作、结果和演示链接。项目贡献和结果按实际确认的材料来写。

## 建议的文件和地址

每篇文章一个文件夹。文件夹名是链接中的固定短名，改文章标题时保留文件夹名。下面是拟采用的结构。

```text
content/blog/
  life/
    weekend-walk/
      index.md
      cover.webp
  projects/
    career-agent/
      index.md
      cover.webp
```

文章的 `index.md` 开头用下面这种格式，字段值是写法示例。

```markdown
---
title: 文章完整标题
spine: 书脊短标题
date: "2026-11-16"
summary: 书架上显示的一句简介。
cover: cover.webp
---

正文从这里开始。
```

分类由文件夹决定，日期用原记录的日期。封面可选。正文中的本地图片相对于文章文件夹引用。构建时从这些文件生成书架数据和静态阅读页，例如 `/blog/entries/life/weekend-walk/`。同一份文章数据用于生成封面、标题和正文页。没有准备好公开的稿件和图片留在公开仓库之外。

## 开发顺序

1. **打通新增流程。** 以一篇生活记录和一篇项目记录做样例，让 `npm run build` 读 Markdown、检查标题和日期、验证封面文件是否存在，并生成书架条目和详情页。正式条目从文章目录生成。空白书只在本地演示时使用。
2. **打通浏览和返回。** 点书脊选中，点正面的封面打开详情。详情链接可直接访问和刷新。返回时恢复上一排、选中的书和焦点。先验证基本行为，再接纸面展开动效。文章增多后，可加一个按日期浏览的目录。
3. **准备发布目录。** 预览继续保留在本地分支。面向 GitHub Pages 的博客文件集中放在 `docs/blog/`，包括博客专用的脚本、样式和文章素材，避免覆盖当前主页共用的 `docs/showcase/`。本地预览用的根目录跳转不进入发布提交。发布前核对文章直达链接、移动端排版、缺图时的文字封面和历史返回。

第一阶段的验收方式是再新增第三篇，只新建文章文件夹与正文或图片，然后运行构建。书架应自动出现对应书本，详情链接可直接打开。
